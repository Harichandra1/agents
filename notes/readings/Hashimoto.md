# Mitchell Hashimoto
## AI Adoption Journey - Notes

## Takeaways
- A chatbot is not enough for real AI usefulness. The real value comes from using agents that can take action, work through context, and complete multi-step tasks.
- For software engineering, AI works best when it is given a clear goal, a structured workflow, and a way to verify the result.
- Good AI usage is not about one huge session. It is better to break work into focused sessions with one clear objective.
- A strong workflow is:
  1. Plan first
  2. Execute second
  3. Verify and correct errors
- Agents should be trusted to catch and fix their own mistakes, especially when there is a test or validation loop.
- At a higher level, agents can be used for deep research, generating multiple ideas in parallel, and automating repetitive developer tasks using tools like GitHub CLI.
- To stay productive, the human should control when to interrupt the agent. Constant notifications create context switching and reduce focus.

## Simple Understanding
- Hashimoto’s main point is this: AI becomes truly valuable when it moves from conversation to execution.
- Instead of asking an AI to “chat,” we should give it tasks that it can carry out in a reliable workflow.
- The best AI systems are not just smart; they are structured, verifiable, and efficient.

## For an AI Engineer
- Design agents around clear tasks, not vague conversations.
- Separate planning from execution to improve reliability.
- Add verification steps such as tests, checks, or self-review to reduce errors.
- Keep agent interactions controlled and intentional, not noisy.
- Use agents for repetitive or high-volume work where they can provide leverage.
- Build systems that help the agent improve itself through feedback and validation.
